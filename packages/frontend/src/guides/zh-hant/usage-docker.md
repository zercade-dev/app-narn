# Docker 使用方式

## 總覽

這個應用程式以 Docker 映像的形式發行，並附有一份 `docker-compose.yml`，會啟動**兩個服務**：`app`（在同一個連接埠同時提供 API 與已建置的介面）以及一個**必要的** `postgres` 資料庫。儲存層全面採用 Postgres，因此伺服器在沒有它的情況下無法啟動。預設情況下，`docker compose up` 會從 GHCR 拉取已發布的 `:main` 映像（`ghcr.io/zercade-dev/narn:main`），並一併啟動官方的 Postgres 17。

## 事前準備

* 已安裝 **Docker** 與 **Docker Compose**。
* 這個應用程式的映像只針對 **amd64** 建置。在 Apple Silicon 上仍然能執行——Docker 會透過模擬方式執行它。
* 如果您帳號下的映像是私有的，請先執行一次 `docker login ghcr.io`（使用具備 `read:packages` 權限的權杖），再進行第一次拉取。

## 執行

在包含 `docker-compose.yml` 的資料夾中——也就是 NARN 原始碼的最上層目錄：

```
docker compose up
```

Compose 會先啟動 Postgres，等待它的健康檢查通過，再啟動 app。app 變成健康狀態後，即可在 `http://localhost:3001` 開啟它。

這個堆疊使用兩個具名磁碟區，讓您的資料在重新啟動後依然保留：

* **`translator-db`**——Postgres 的資料目錄，您的**專案**與**翻譯記憶庫**都存放在這裡。
* **`translator-data`**——本機的保險庫檔案，以及各專案的備份與自動快照。

Postgres 不會發布任何主機連接埠，只存在於 Docker 的內部網路中，因此只有 app 容器能連線到它。

## 變更主機連接埠

容器在 Docker 內部一律監聽 **3001** 連接埠。compose 檔案會把它對應到您機器上相同的連接埠：

```
ports:
  - "127.0.0.1:3001:3001"
```

如果 3001 連接埠已被占用，請變更對應設定的**左（主機）側**——也就是第二個冒號之前的部分。舉例來說，若要改用 8000 連接埠提供服務：

```
ports:
  - "127.0.0.1:8000:3001"
```

之後就可以在 `http://localhost:8000` 存取這個應用程式。

**請勿**變更 `HOST` 或 `PORT` 環境變數——這兩者是容器內部使用的（伺服器在容器內綁定 `0.0.0.0:3001`，以便 Docker 能轉發連線）。只有 `ports` 對應設定的主機端，才會控制您機器上的存取位址。

`127.0.0.1:` 這個前綴會讓應用程式維持只綁定於本機（loopback），以保持單一使用者、僅限本機的定位。除非您有刻意要對外公開這個應用程式的理由，否則請保留這個設定。
