# การใช้งาน Docker

## ภาพรวม

แอปเผยแพร่เป็น Docker image พร้อมไฟล์ `docker-compose.yml` ที่เปิด**สองบริการ**ขึ้นมา: `app` (ซึ่งให้บริการทั้ง API และ UI ที่ build แล้วบนพอร์ตเดียว) และฐานข้อมูล `postgres` ที่**จำเป็นต้องมี** พื้นที่จัดเก็บข้อมูลใช้ Postgres ทุกจุด เซิร์ฟเวอร์จึงบูตไม่ได้หากไม่มีฐานข้อมูลนี้ โดยค่าเริ่มต้น `docker compose up` จะดึง image ที่เผยแพร่ไว้ `:main` (`ghcr.io/zercade-dev/narn:main`) จาก GHCR และเริ่ม Postgres 17 อย่างเป็นทางการควบคู่กันไป

## ข้อกำหนดเบื้องต้น

* ติดตั้ง **Docker** และ **Docker Compose** แล้ว
* image ของแอป build มาสำหรับสถาปัตยกรรม **amd64** เท่านั้น บน Apple Silicon ก็ยังรันได้ — Docker จะรันผ่านการจำลอง
* หาก image เป็นแบบส่วนตัวสำหรับบัญชีของคุณ ให้รัน `docker login ghcr.io` หนึ่งครั้ง (ด้วยโทเคนที่มีสิทธิ์ `read:packages`) ก่อนดึง image ครั้งแรก

## การรัน

จากโฟลเดอร์ที่มี `docker-compose.yml` — จุดบนสุดของซอร์ส NARN:

```
docker compose up
```

Compose จะเริ่ม Postgres ก่อน รอ healthcheck ของมัน แล้วจึงเริ่มแอป เมื่อแอปพร้อมใช้งานแล้ว ให้เปิดที่ `http://localhost:3001`

สแต็กนี้ใช้ named volume สองตัวเพื่อให้ข้อมูลของคุณอยู่รอดหลัง restart:

* **`translator-db`** — ไดเรกทอรีข้อมูลของ Postgres ที่เก็บ**โปรเจกต์**และ**หน่วยความจำการแปล**ของคุณ
* **`translator-data`** — ไฟล์ตู้นิรภัยในเครื่อง บวกกับข้อมูลสำรองและสแนปช็อตอัตโนมัติต่อโปรเจกต์

Postgres ไม่เปิดพอร์ตของ host และอยู่บนเครือข่ายภายในของ Docker เท่านั้น จึงเข้าถึงได้เฉพาะจากคอนเทนเนอร์ของแอป

## การเปลี่ยนพอร์ตของ host

คอนเทนเนอร์จะฟังที่พอร์ต **3001** ภายใน Docker เสมอ ไฟล์ compose จับคู่พอร์ตนี้กับพอร์ตเดียวกันบนเครื่องของคุณ:

```
ports:
  - "127.0.0.1:3001:3001"
```

หากพอร์ต 3001 ถูกใช้งานอยู่แล้ว ให้เปลี่ยนฝั่ง**ซ้าย (host)** ของการจับคู่ — ส่วนก่อนเครื่องหมายโคลอนตัวที่สอง ตัวอย่างเช่น เพื่อให้บริการที่พอร์ต 8000:

```
ports:
  - "127.0.0.1:8000:3001"
```

จากนั้นแอปจะเข้าถึงได้ที่ `http://localhost:8000`

**ห้าม**เปลี่ยนตัวแปรสภาพแวดล้อม `HOST` หรือ `PORT` — ตัวแปรเหล่านั้นเป็นแบบภายในคอนเทนเนอร์ (เซิร์ฟเวอร์ผูกกับ `0.0.0.0:3001` ภายในคอนเทนเนอร์เพื่อให้ Docker ส่งต่อคำขอมาได้) มีเพียงฝั่ง host ของการจับคู่ `ports` เท่านั้นที่ควบคุมที่อยู่บนเครื่องของคุณ

คำนำหน้า `127.0.0.1:` ทำให้แอปผูกกับ loopback เท่านั้น รักษาลักษณะการใช้งานคนเดียวและใช้ได้เฉพาะในเครื่องไว้ ให้คงไว้แบบนี้ เว้นแต่คุณมีเหตุผลตั้งใจที่จะเปิดให้แอปเข้าถึงจากภายนอก
