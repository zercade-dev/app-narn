# 자격 증명 보관함

## 개요

제공업체 API 키는 일반 설정 파일이나 환경 변수에 절대 보관하지 않아요. 이런 키는 **자격 증명 보관함**에 있어요 — 번역이나 AI 검토가 자격 증명을 쓰려면 먼저 잠금을 해제해야 하는 암호화된 저장소예요. 브라우저 세션마다 한 번 잠금을 해제하며, 자격 증명은 메모리에서만 복호화돼요.

<!-- local-only -->
## 비밀번호 보관함 (셀프 호스팅)

셀프 호스팅 설치에서 보관함은 암호화된 로컬 파일이에요. 처음 잠금을 해제할 때 파일이 만들어져요: 이때 정한 비밀번호가 보관함 비밀번호가 되고, 자격 증명을 저장할 때마다 파일이 다시 암호화돼요. 비밀번호 자체는 저장되지 않아요 — 비밀번호가 없으면 파일을 복호화할 수 없어요. **글로벌 설정**에서, 또는 *보관함 잠김* 카드 어디서든 잠금을 해제할 수 있어요.

## 기기 기반 보관함 (클라우드)

클라우드 버전에서 보관함은 **서버에 암호화된 상태로 저장**되며, 복호화하려면 두 가지 요소가 필요해요.

- **비밀번호** — 서버든 기기든 어디에도 저장되지 않아요.
- **기기별 키** — 기기를 등록할 때 브라우저에서 생성되며, 그 기기에만 남아 있어요.

잠금을 해제하면 두 요소가 암호화된 연결을 통해 전송되고, 서버 쪽에서 결합되어 **메모리에서, 그 세션 동안만** 복호화 키를 만들어요. 두 요소도 만들어진 복호화 키도 서버 저장소에 기록되지 않아요 — 저장되는 건 암호화된 보관함 자체뿐이에요. 그래서 서버에 저장된 데이터만으로는 자격 증명을 알아낼 수 없고, 비밀번호가 유출되는 것만으로도 부족해요 — 잠금을 해제하려면 등록된 기기 중 하나도 있어야 해요.

글로벌 설정에 비밀번호 입력창 대신 **보관함 페이지로 이동** 버튼이 보인다면, 기기 기반 보관함을 쓰고 있는 거예요 — 보관함 페이지에서 설정, 기기 등록, 잠금 해제, 자격 증명 편집, 비밀번호 변경을 모두 처리해요.

## 알아 두면 좋은 것

- 한 번도 쓰지 않은 기기는 잠금을 해제하기 전에 보관함 페이지에서 먼저 **등록**해야 해요.
- 비밀번호를 잃어버리면(클라우드에서는 등록된 기기를 모두 잃으면) 보관함 내용을 복구할 수 없어요 — 보관함을 다시 설정하고 제공업체 키를 다시 입력해야 해요.
- 앱이 기록하는 모든 로그는 정보 가림 처리를 거치므로, 자격 증명 값이 로그에 나타나는 일은 없어요.
