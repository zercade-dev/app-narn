# Docker 사용법

## 개요

이 앱은 Docker 이미지와 `docker-compose.yml`로 배포되며, **서비스 두 개**를 함께 띄워요: `app`(API와 빌드된 UI를 한 포트에서 함께 제공)과 **필수**인 `postgres` 데이터베이스예요. 저장소는 어디서나 Postgres를 쓰므로, 서버는 Postgres 없이는 켜지지 않아요. 기본적으로 `docker compose up`은 GHCR에 게시된 `:main` 이미지(`ghcr.io/zercade-dev/narn:main`)를 내려받고, 공식 Postgres 17을 함께 시작해요.

## 사전 준비

- **Docker**와 **Docker Compose**가 설치되어 있어야 해요.
- 앱 이미지는 **amd64** 전용으로 빌드돼요. Apple Silicon에서도 실행은 되지만, Docker가 에뮬레이션으로 실행해요.
- 계정에서 이미지가 비공개라면, 처음 내려받기 전에 `read:packages` 권한이 있는 토큰으로 `docker login ghcr.io`를 한 번 실행하세요.

## 실행하기

`docker-compose.yml`이 있는 폴더 — NARN 소스의 최상위 폴더 — 에서:

```
docker compose up
```

Compose는 Postgres를 먼저 시작하고, 헬스체크를 기다린 다음 앱을 시작해요. 앱이 정상 상태가 되면 `http://localhost:3001`에서 열어 보세요.

이 스택은 이름 붙은 볼륨 두 개를 사용하므로, 재시작해도 데이터가 남아 있어요.

- **`translator-db`** — Postgres 데이터 디렉터리로, **프로젝트**와 **번역 메모리**가 저장돼요.
- **`translator-data`** — 로컬 보관함 파일과 프로젝트별 백업, 자동 스냅샷이에요.

Postgres는 호스트 포트를 열지 않고 Docker 내부 네트워크에만 있으므로, 앱 컨테이너에서만 접근할 수 있어요.

## 호스트 포트 바꾸기

컨테이너는 Docker 내부에서 항상 **3001** 포트로 대기해요. compose 파일은 이를 사용자 컴퓨터의 같은 포트로 매핑해요.

```
ports:
  - "127.0.0.1:3001:3001"
```

3001 포트가 이미 쓰이고 있다면, 매핑의 **왼쪽(호스트) 쪽** — 두 번째 콜론 앞부분 — 을 바꾸세요. 예를 들어 8000 포트로 제공하려면:

```
ports:
  - "127.0.0.1:8000:3001"
```

그러면 앱은 `http://localhost:8000`에서 접근할 수 있어요.

`HOST`나 `PORT` 환경 변수는 **바꾸지 마세요** — 이건 컨테이너 내부용이에요(서버는 컨테이너 안에서 `0.0.0.0:3001`에 바인딩되어 Docker가 요청을 전달할 수 있게 해요). 사용자 컴퓨터의 주소를 결정하는 건 `ports` 매핑의 호스트 쪽뿐이에요.

`127.0.0.1:` 접두사는 앱을 루프백에 묶어 두어, 단일 사용자·로컬 전용 방침을 유지해요. 앱을 외부에 노출할 뚜렷한 이유가 없다면 그대로 두세요.
