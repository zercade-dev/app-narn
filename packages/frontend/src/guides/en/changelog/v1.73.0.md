## v1.73.0 — 2026-09-12

Deleting your account now clears every last piece of data it left behind.

- Manual edit history, and the usage and provider records behind free-tier routing, are removed along with everything else.
- Three newer tables had been added since the deletion routine was written and were not on its list.
- The routine now derives that list from the database itself, so a future addition cannot be missed.

The Activity tab now stays quick on projects with a long run history.

- While a run is in progress the list refreshes every couple of seconds, and it no longer re-sends each run's full internal job list every time.
- Projects with many past runs, or a large run parked waiting for free quota, load and refresh noticeably faster, and use far less data on a metered connection.
- Everything the Activity tab shows is unchanged, including how many pairs a parked run is still waiting on.

The Activity tab's run history is lighter to load on a project with a long run history.

- The runs list your browser polls every couple of seconds while a run is active now stays a fixed size instead of growing with every run a project has ever had.
- Anything currently running or queued always still shows up — only very old, finished runs are the ones trimmed from the list.

AI review no longer spends your quota on Pseudo Test strings.

- Reviewing a whole project used to send every deliberately-garbled Pseudo Test translation to the AI, which flagged them all and dragged the review's average score down.
- Pseudo Test is now left out of every AI review, so the flagged count and average score describe your real translations only.
- The review dialog no longer offers Pseudo Test as a language to review, and a project whose only language is Pseudo Test now tells you there is nothing to review instead of starting a review that cannot help.

Exporting your audit log now includes the events recorded today, not just the archived files.

- The export used to read only the archived log files, so everything recorded since the last archive was left out — after a restart, that was the whole retained window.
- The current log is now merged in, and an event that appears in both places is counted once rather than twice.
- Narrowing an export by event type or time range now applies to the file entries too, so the exported count means what it says.

Restoring a project from a backup file now only ever replaces a project you own.

- Uploading a backup archive confirms the project it names belongs to you before anything is written.
- Restoring into a brand-new project, or one you deleted earlier, works exactly as before.
- A restore that is refused leaves the existing project completely untouched.

Restoring from an uploaded backup file now tells you which project it will overwrite.

- The confirmation names the project the archive belongs to, along with when it was taken and how many files it holds.
- An archive that belongs to a project other than the one you are looking at is called out before you commit to the restore.
- If the archive names a project that is not here yet, the confirmation says the restore will create it rather than replace anything.

A batch of translations that comes back with confused numbering is now rejected instead of being saved against the wrong entries.

- Some AI models answer a batch by numbering each translation; when two of them carried the same number, the first translation was quietly saved onto the second entry as well.
- Those batches are now reported as failed, so the entries stay in Activity for a retry instead of gaining a translation that belongs to a different string.
- Replies that number their translations sensibly — in any order, and whether they start at zero or one — keep working exactly as before.

Switching projects while the Categories tab is open now shows the project you switched to, never the one you left.

- A category list that was still loading for the previous project no longer lands on top of the new project's tabs a moment later.
- The AI suggestion review panel, the selected category and any open dialog are cleared by the switch, so suggestions made for one project can never be applied to another.
- While the new project's categories load, the tab strip shows its loading state instead of the previous project's list.

An AI-assistant reply cut short by a provider failure now says so, instead of looking like a finished answer.

- If the provider drops out once the reply has started, the text that arrived is still kept — but the chat now shows the error next to it, so half an answer is no longer mistaken for a short one.
- Both the Text Styler assistant and the stage-details assistant are covered.
- Stopping a reply yourself is unchanged: the text already on screen stays, with no error.

An AI-assistant turn that fails immediately is now recorded as failed instead of sitting in Activity as "running" forever.

- Turns that failed before they got going — an assistant pointed at a deleted connection, or a missing provider key — could leave the chat session stuck as running, sometimes without the error that caused it.
- A stuck row also counted towards the limit on how many runs you can have going at once, so unrelated translations could start being turned away.
- Both the Text Styler and the stage-details assistant are covered, and a turn that fails this way is no longer counted twice in the session's turn total.

Shared projects no longer show collaborators buttons that were always going to be refused.

- The right-click menu's category and glossary panels now open as a read-only view for collaborators: the entry's categories and its enabled glossaries stay visible, but the add, remove and save controls are gone.
- On the Glossary tab, the enable/disable button, Import, both "push to DeepL" buttons, the rename and delete icons on a glossary, and the assign action in the matches panel are hidden for collaborators, matching the ones that were already owner-only.
- If one of these actions is refused anyway — because your access changed while you were working, say — the app now tells you instead of appearing to do nothing.

Keyboard shortcuts in the Compare tab no longer fire when you hold Ctrl, Cmd, Alt or Shift.

- Ctrl+C and Cmd+C copy the cell again instead of clearing the translation.
- Ctrl+R and Cmd+R reload the page again instead of marking the cell reviewed.
- The plain c, r and t shortcuts are unchanged, including with CapsLock on.

Rich mode in the Compare tab no longer floods the app with one tag-parsing request per row on the page.

- Formatting is parsed a few cells at a time, so opening a large page in Rich mode no longer slows the rest of the app down.
- Turning a page, changing the compared language or leaving the tab drops the parses still waiting instead of letting them finish in the background.
- Dropping them is never treated as a failure, so cells you come back to still show their formatting rather than raw markup.

Translations from GitHub Copilot no longer keep stray HTML codes in place of ordinary punctuation.

- A model that writes an apostrophe as `&#39;` or a space as `&nbsp;` now has those turned back into real characters before the translation is saved.
- Every other AI provider already did this, so the same model could give a clean result through one provider and a corrupted one through Copilot.
- Affected entries no longer raise the "HTML entity" quality warning, and exported text comes out clean.
- A code your source text genuinely contains is still left exactly as it is.

Importing a CSV now catches rows cut short by a stray quote, instead of quietly filing their values under the wrong columns.

- A quote sitting just before the end of a line used to end the row early, so every value after it shifted one column to the left.
- Those rows are now left out of the import and reported in the import summary, alongside the ones that had too many columns.
- Rows that simply leave their last few columns empty still import exactly as before.

Custom AI endpoints on the hosted service can no longer point at an address on the server itself.

- On the hosted service, a custom endpoint set to `localhost` or `127.0.0.1` is now refused with a clear message — that address is the service's own machine, never yours.
- Running your own copy is unchanged: a local model such as Ollama or LM Studio on `localhost` keeps working exactly as before.
- A shared instance hosted with a model running alongside it can re-permit that address with a single operator setting.

DeepL returns to the free-provider rotation minutes after a busy signal, instead of sitting out the rest of the month.

- A brief DeepL rate limit used to set DeepL aside until its monthly character allowance reset, with no way to bring it back sooner.
- It is now set aside for a short cool-down and picked up again on the next run; a genuinely used-up allowance is still recognised separately.
- Usage figures fetched from DeepL and OpenRouter are now dropped when they arrive too late to be trusted, so remaining free-provider quota stays accurate.

You can now turn off a provider for NARN Freeway without touching your routing rules.

- Every free provider's Freeway selector now offers a "Disabled" option alongside Automatic and any named instances.
- Freeway skips a disabled provider for every new run until you turn it back on; a run that is already in progress may finish on the model it started with.
- DeepL now gets its own selector too, so it can be included or excluded from Freeway the same way as every other provider.
- An AI review or source review that is already running moves off a provider at its next batch once you disable it, instead of finishing on it.

AI review runs on free providers now recover from a rate limit instead of failing the whole batch.

- A translation review or source review that hits a provider's rate limit waits out that provider's own cool-down and retries, rather than reporting every item in the batch as failed.
- If the provider is still out of capacity, the run moves the batch to another free provider once, and sets the exhausted one aside for the rest of the run.
- Reviews running on your own provider key are unchanged: a busy provider is still handled by retrying smaller and smaller batches.

Picking Minimal thinking on a Gemini 3 model no longer quietly falls back to Medium.

- Minimal was offered in the thinking-effort list but sent as Medium, so the cheapest setting could think — and cost — as much as the middle one.
- It now runs at the lowest thinking level the whole Gemini 3 family reliably accepts.
- Low, Medium and High are unchanged.

Saving a glossary term as a collaborator now keeps every other language's entry intact.

- Editing a term in a language you were granted no longer clears that term's other languages.
- Owners and other collaborators see the term exactly as it was, apart from the language that was edited.
- Clearing a single language still works: empty its box and save.

Glossary terms written in the Latin alphabet are now recognized inside Japanese, Chinese, Korean and Thai text.

- A term such as "HP" was previously missed whenever it sat directly against Japanese, Chinese, Korean or Thai characters, because those languages are written without spaces between words.
- Projects whose source text is in one of those languages now get the right glossaries assigned automatically, and the term reaches the model together with the wording you require for it.
- The forbidden-term and glossary-adherence quality checks read translations in those languages correctly too, so they no longer miss a real problem or flag a correct translation.

Opening a glossary no longer says it has no terms while its terms are still loading.

- The "No terms in this glossary yet" message now waits for the selected glossary's terms to arrive, so a glossary full of terms is never announced as empty for a moment first.
- Switching between glossaries behaves the same way: the message shows only for a glossary that has finished loading and is genuinely empty.

The Strings and Compare tabs stay responsive while a run streams its log.

- Both tables used to redraw five times a second for the whole length of a run, whether or not anything on screen had changed.
- They now redraw only when something they actually show moves: a cell starting or finishing, or that run's own progress count.
- Large projects with many visible languages benefit the most, and nothing about what the tables display has changed.

Setting HOST to an empty value no longer starts the server on every network interface by mistake.

- A blank or whitespace-only `HOST` now means the all-interfaces address it really binds, not the loopback-only default.
- A hosted instance refuses to start on that setting unless it has been configured deliberately.
- A `HOST` written with stray spaces around it is trimmed, instead of failing to start at all.

Imports now stop with a clear message if your account has a string limit and the file would take you past it.

- The message says how many strings you already have, what the limit is, and how many the import would add, so you know how much to clear out.
- Nothing is written when an import is refused, so there is never a half-finished import to undo.
- Re-importing a file that only updates strings you already have is never refused, even when you are right at the limit.
- The preview refuses too, so it can no longer show you a summary of an import that would then fail.
- Accounts with no limit set, including narn running on your own machine, are unaffected.

Server log lines now hide a provider key that the provider's own error text echoed back.

- The log panel and the server console already masked any stored key that turned up in a log entry's details, but not one that turned up in the line's own wording.
- A failed model-list request to a provider that quotes the rejected key back in its reply could put that key straight into the line, where it stayed readable.
- The wording of every log line is now checked the same way its details already were, so the key is masked wherever it appears.

The model picker's list can now be used from the keyboard alone.

- Choosing a model used to need a mouse — the rows in the model dialog could not be reached or activated with the keyboard at all.
- Press the down arrow from the search box to step into the list, move with the arrow keys or Home and End, then press Enter or Space to choose the highlighted model.
- The row the keyboard is on is now outlined, and screen readers announce which model is currently selected.

The module health view now shows only your own activity.

- Provider health counts, model names and instance names are scoped to your account.
- Previously the shared cloud service reported everyone's figures to everyone.

Deleting several orphaned entries at once now asks you to confirm first.

- Choosing "Delete selected" on the Orphans tab opens the same confirmation the single-row Delete button already showed, and says how many records it will remove.
- Orphan deletion is permanent — the entries and every translation on them go with it — so the bulk action no longer runs straight from one click.

Opening a large project is lighter on the server, and quicker over a slow connection.

- The full string list is now sent as it is read, rather than being assembled in one piece first — so a big project no longer makes everyone else's requests wait while it is put together.
- On the hosted service that list is now compressed on the way to you, which cuts what a project with many languages costs to download, and stops a slow link timing out part-way through.
- Nothing about the list itself changes: the same entries arrive in the same order, and orphaned entries are still left out.

Provider API keys are now consistently kept in the credential vault, for every provider.

- Saving a key into a provider's settings is refused, the same way it already was for DeepL.
- Eight providers previously accepted a key there, and used it in preference to the one in your vault.
- Keys already stored that way are hidden from the settings screens and stripped from exports.

Each AI provider connection now keeps its own request pacing and parallel-request limit.

- A connection set to run one request at a time now really does, even while another connection to the same provider is busy.
- Two named connections to one provider no longer take turns in a single queue, so one can't hold up the other.
- Your requests-per-second setting now paces only your own translations.

A translation still waiting in the queue when the app restarts now runs properly when you press Start now.

- Starting one that way used to leave it without access to your unlocked vault, so every string failed with a missing-credentials error.
- It now runs under the session you started it from, exactly like any other run.
- Nothing reached an AI provider in that state, so a run caught by this never cost anything — retrying its failed strings was always enough.

Relink retranslation now protects the placeholders in your source text, and flags a translation that comes back missing one.

- Placeholders like `{0:playerName}`, inline styling tags and line breaks are hidden behind protected tokens before the string is sent to the AI, so a model updating an existing translation can no longer rename, translate or drop one.
- A reply that loses or invents a placeholder is saved with a blocking quality issue instead of quietly replacing a working translation with a string your game cannot format.
- This is the same protection ordinary translation runs have always had; relink was the one route that sent its text through unprotected.

Relinking a string no longer sends its Pseudo Test text to a paid AI provider.

- The AI retranslate pass that follows a relink now skips the Pseudo Test language, the same way every other translation route does.
- Your pseudo-localized text stays exactly as it was, instead of being replaced by a model's answer and billed for.
- The run's progress count and the languages it lists now cover only the languages it actually retranslates.

Restarting or updating the app now lets whatever it was already doing finish, instead of cutting it off the moment the shutdown starts.

- Exports, downloads and other requests that were already under way now complete rather than failing partway through.
- The app used to close its database connection the instant a shutdown began, so anything still in progress failed immediately.
- Live activity and log streams are now closed properly, so a restart finishes on its own instead of having to be forced.

Retry failed now works on a run you cancelled, instead of quietly doing nothing.

- A run that stopped because a provider rejected your API key can be retried once you fix the key, and the failed entries are genuinely sent again.
- Before this, the button reported that a retry had started and nothing happened.
- A retried cancelled run now finishes properly instead of staying stuck in progress and holding up the project's other runs.

Building the review order for a very large project no longer freezes the server for everyone using it.

- The similarity pre-sort now caps how much of its index it searches per step, not just how many neighbours it keeps.
- On a large project where one word appears in almost every string, that search could previously run for minutes while the server answered nothing at all.
- The resulting order can differ slightly on projects of that size, since fewer candidates are compared. Ordinary projects are unaffected.

Every reasoning effort a model offers can now be set as a routing-rule override.

- Choosing Minimal, Enabled or Max on a rule was rejected when the change was saved, and because the rules save together, the rest of the routing configuration did not save either.
- Only Low, Medium, High, Xhigh and Disabled were accepted, even though the dropdown offers whichever levels the chosen model supports.
- The accepted levels now come from the same list the dropdown is built from, so a level added for a future model works straight away.
- The same applies to a collaborator's personal routing and to importing a project template, which check rules the same way.

Big translation runs and bulk approvals now repeat far less work behind the scenes, so they finish sooner and leave the app responsive.

- The automatic quality check on each finished translation used to re-read the whole project first, once for every string and language a run produced.
- Approving a large selection re-read your glossaries once per approved translation; it now reads them once per language, exactly as a translation run does.
- The checks and the approvals themselves are unchanged: same verdicts, same terms, same results.
- Quality-check settings you change while a run is under way now take effect on the next run, or when a paused run resumes, rather than part-way through the one already going.

Filtering the string table by a run keeps showing the entries you have touched since that run finished.

- Clearing a "needs review" flag, approving a translation, or changing an entry's settings no longer drops it out of the run that translated it.
- Replacing a translation's text by hand still detaches that entry from the run, so a run only ever lists the text it actually produced.

Retrying or resuming a translation run now stays inside the languages you are allowed to edit.

- A collaborator can retry a run only when every language that failed is one of theirs.
- Resuming a run, including choosing a specific provider for a paused one, takes the same check.
- Changing someone's languages now applies to the runs they already started, not only to new ones.
- Project owners can still retry and resume any run in their project, exactly as before.

Reverting a translation run now stays inside the languages you are allowed to edit.

- A collaborator can revert a run only when every language it touched is one of theirs.
- A run that also touched another language is refused outright, rather than left half reverted.
- Project owners can still revert any run in their project, exactly as before.

A translation run that fails to get started no longer blocks everything queued behind it.

- If something goes wrong while a run is being set up, the run is now marked failed instead of sitting there as "running" with no work to do.
- Previously the project's queue stalled behind it, and the only way out was to cancel the stuck run or restart the server.
- Retrying a run that was still going when the server last restarted no longer risks it being marked failed while it is running.

The Settings page now has its own address, so a reload or the Back button keeps you there.

- Opening Settings no longer rewrites the address bar to the project's Config tab.
- Reloading the page stays on Settings instead of dropping you back on Config.
- After leaving Settings, the browser's Back button returns you to it, and you can bookmark or link to it directly.

Switching projects while the Sharing tab is open now clears any unsaved changes to a collaborator's languages.

- Language boxes you ticked for a collaborator but did not save no longer follow you into the next project, where saving would have applied them there instead.
- A save or a removal still in flight when you switch can no longer change what the new project's member list shows.
- The member list, the names on it and any open confirmation are all reset by the switch, so nothing from the project you left is left on screen.

Changing a project's source language now keeps the target-language ticks you had not saved yet.

- Previously the change quietly ignored those unsaved ticks, then left them staged, so pressing Save afterwards could add the new source language back to the target list — a combination the project should never be in.
- The source-language change now saves your staged target list along with it, minus the language you just promoted to source, and the unsaved-changes prompt clears once it is stored.

Editing your Stage details no longer asks you to unlock the vault.

- Stage details text is your own writing, so saving it never touches an AI provider key — but the save was being held behind the same lock a translation run uses, and refused until you unlocked.
- Saving now works with the vault locked, and no password prompt interrupts the edit.
- Translating your Stage details, and its chat assistant, still ask for the vault as before.

Editing a translation in the string table no longer clears its "needs review" flag or credits your edit to the AI.

- A translation the AI review flagged stays in the review queue after you fix it by hand, so nothing drops out unreviewed.
- Your edited text is now attributed to you rather than to the model that wrote the version you replaced.
- The quality tier recorded for the old machine translation no longer sticks to your hand-written text.
- Clearing the flag is still the explicit "Clear \"needs review\" flag" action in the row's right-click menu.

The Text Styler no longer freezes on pasted text whose style tags were never closed.

- Text with unmatched or mistyped tags now previews instantly, however long the passage is.
- Unclosed tags still show as ordinary text, exactly as before — only the delay is gone.
- Very deeply nested tags, which could stop the page with an error, now render normally.

Leaving the Text Styler tab while the assistant is still replying now stops the reply instead of letting it run on in the background.

- Switching tabs or closing the project cancels the turn with your AI provider, so you are no longer charged for text nobody is there to read.
- A turn cancelled this way is recorded in Activity as cancelled, with the tokens it used up to that point.
- The Stop button is unchanged: it still ends the turn and keeps the part of the reply already on screen.

The Translate dialog's "already in translation memory" figure now appears quickly even when you select a whole project across many languages.

- Previously the estimate re-read your glossaries once for every string-and-language pair, so a large selection could leave the dialog waiting and slow the server for everyone else on it.
- The glossaries are now read once per language instead, which is exactly what a real translation run does.
- For very large selections the figure is now based on the first several thousand pairs rather than every last one, so it can read low. It stays an estimate either way — the run itself is unaffected.

Entering a wrong two-factor code at sign-in no longer locks you out of the attempt.

- The verification form stays open after a wrong or expired code, so you can simply try again.
- If the authentication service asks you to wait before retrying, the sign-in page now tells you how long.
- Verify is disabled while a code is being checked, so a double press cannot strand the sign-in.

Closing the vault password prompt without unlocking no longer leaves the button you pressed stuck.

- Dismissing the prompt now cancels whatever action was waiting on it, so the button works again straight away.
- Before this, the only way to get the button back was to reload the page.
- Unlocking normally still replays everything that was waiting, exactly as before.
