# Docker 使用说明

## 概述

本应用以 Docker 镜像的形式发布，并附带一个 `docker-compose.yml`，它会启动**两个服务**：`app`（在同一个端口上同时提供 API 和构建好的界面）以及一个**必需的** `postgres` 数据库。存储是全程 Postgres 化的，因此服务器在没有它的情况下无法启动。默认情况下，`docker compose up` 会从 GHCR 拉取已发布的 `:main` 镜像（`ghcr.io/zercade-dev/narn:main`），并在旁边启动一个官方的 Postgres 17。

## 前提条件

* 已安装 **Docker** 和 **Docker Compose**。
* 该应用镜像仅为 **amd64** 构建。在 Apple Silicon 上它仍可运行——Docker 会通过模拟方式执行它。
* 如果该镜像对您的账户是私有的，请在首次拉取前运行一次 `docker login ghcr.io`（令牌需具备 `read:packages` 权限）。

## 运行

在包含 `docker-compose.yml` 的目录中——即 NARN 源码的顶层目录：

```
docker compose up
```

Compose 会先启动 Postgres，等待其健康检查通过，然后再启动 app。app 变为健康状态后，即可通过 `http://localhost:3001` 打开它。

该技术栈使用两个命名卷，让您的数据在重启后依然保留：

* **`translator-db`**——Postgres 数据目录，您的**项目**和**翻译记忆库**都保存在这里。
* **`translator-data`**——本地保险库文件，以及各项目的备份和自动快照。

Postgres 不对外发布主机端口，而是位于 Docker 内部网络中，因此只有 app 容器能够访问它。

## 更改主机端口

容器内部始终监听 **3001** 端口。compose 文件将其映射到您机器上的同一端口：

```
ports:
  - "127.0.0.1:3001:3001"
```

如果 3001 端口已被占用，请更改映射的**左（主机）侧**——即第二个冒号之前的部分。例如，要改用 8000 端口对外提供服务：

```
ports:
  - "127.0.0.1:8000:3001"
```

之后即可通过 `http://localhost:8000` 访问该应用。

**不要**更改 `HOST` 或 `PORT` 环境变量——它们是容器内部使用的（服务器在容器内绑定 `0.0.0.0:3001`，以便 Docker 能够转发到它）。只有 `ports` 映射的主机侧才控制您机器上的访问地址。

`127.0.0.1:` 前缀让应用始终绑定在回环地址上，保持单用户、仅限本地访问的姿态。除非您有意要对外暴露该应用，否则请保留此设置。
