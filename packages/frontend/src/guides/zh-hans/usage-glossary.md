# 术语表标签页

## 概述

**术语表**标签页用于保持术语一致。一个项目可以拥有多个术语表；每个术语表都是一份原文术语列表，每种目标语言各有一条译文。术语表会自动与条目进行匹配，匹配到的术语会在翻译时传递给模型。

## 术语表与术语

* 用**新建术语表**创建一个术语表；之后可以重命名或删除。
* **启用**或**停用**某个术语表——已停用的术语表在导入和翻译时都会被忽略。
* 添加术语时填写**原文**、**每种语言的译文**，以及可选的**备注**。
* 当某个术语必须完全按术语表中的写法输出时（例如角色名或品牌名），将其标记为**常量**。详见下方的*常量术语*。
* 术语表有两个标签页：**术语**列出它的术语，**匹配项**列出包含这些术语的条目，你可以在那里为条目分配或移除术语表。

部分术语表是**只读**的（由全局管理），它们提供术语，但不能在这里编辑。

## 常量术语

* 常量术语**永远不会发送给翻译引擎**。NARN 在翻译前用占位符替换它，翻译后再在原位放入术语表中的译法，因此像 *Diluc* 这样的角色名总会和术语表中写的完全一致。
* **区分大小写。**只有与术语写法完全一致的文本才受保护：*Venti*（角色）受保护，*a venti latte* 不受保护。其他写法会作为普通术语提示发送给引擎，并标记为名称，让引擎区分名称和普通词语。
* **引擎无法改动这个词。**由于引擎看不到该术语，它无法对其进行变格，也无法让其他词与之一致：在俄语、韩语或土耳其语等语言中，常量名称总是以原形出现。请只把常量用于必须保持不变的名称和代码。
* 同时也是普通词语的名称最好保留为普通术语，因为标题和标签常把它们首字母大写（*Gaming Settings*）。在内置术语表中，角色名、国家名以及产品名 Genshin Impact, Miliastra Sandbox 和 Miliastra Wonderland 都是常量，但 Gaming, Amber, Razor, Sucrose, Prune, Traveler 和 Wanderer 除外。

## 导入和导出

从 **CSV** 或 **TBX** 导入术语——应用前会先显示预览，说明有多少术语会被新增、更新或产生冲突。也可以将术语表导出回 **CSV** 或 **TBX**。

## 用 AI 生成

* **生成术语表**会扫描原文，针对反复出现的名称和自定义术语提出术语表建议。它会在后台运行——可在**活动**标签页中跟踪，并在创建之前先审校建议。您可以把已有的术语表作为"已知内容"传入，这样模型就不会重复它们。
* **生成译文**会为仍缺少目标语言译文的术语补全译文。

## DeepL

如果您使用 DeepL 翻译，请使用**推送到 DeepL** 上传术语表内容。编辑一个已推送的术语表后，该标签页会显示"需要重新推送"——请再次推送以更新 DeepL。

## 按条目控制

在译文标签页中，您可以为单个条目选择启用哪些术语表。
