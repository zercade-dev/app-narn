# Модуль Generic AI

## Обзор

Модуль **Generic AI** подключается к любому API, совместимому с OpenAI, — размещенному у поставщика или к локально запущенному серверу (например, Ollama, LM Studio, vLLM). Его ключ хранится в хранилище учетных данных под `GENERIC_API_KEY`.

**API-ключ необязателен.** Он важен только для конечных точек, требующих аутентификации (большинство платных облачных поставщиков). Локальному серверу вроде Ollama или LM Studio настоящий ключ не нужен — но хранилище все равно требует, чтобы поле `GENERIC_API_KEY` было непустым, поэтому сохраните туда любую заглушку (например, `local`), чтобы удовлетворить это требование.

## Добавление ключа в хранилище учетных данных

Учетные данные поставщиков хранятся в зашифрованном **хранилище учетных данных**, а не в открытой конфигурации. Хранилище разблокируется паролем один раз за сеанс.

1. Откройте **Глобальную конфигурацию** в боковой панели.
2. Если хранилище еще не настроено, создайте его: выберите пароль хранилища (вы будете вводить его в каждом сеансе) и разблокируйте хранилище.
3. В разделе **Включить модуль** выберите **Generic AI**. Если нужный ключ отсутствует, редактор хранилища автоматически откроется на нужном ключе — в противном случае нажмите **Управление хранилищем учетных данных**.
4. В редакторе хранилища добавьте учетные данные: выберите ключ `GENERIC_API_KEY`, введите **пароль хранилища** и нажмите **Сохранить**. Для платной конечной точки вставьте в качестве значения настоящий API-ключ. Для локального сервера, которому аутентификация не нужна, ключ необязателен — просто сохраните любую непустую заглушку (например, `local`).

## Работа с несколькими конечными точками через экземпляры

Generic AI поддерживает **именованные экземпляры**, поэтому можно зарегистрировать сразу несколько конечных точек (например, один облачный поставщик и один локальный сервер). Используйте **Добавить еще один экземпляр Generic AI** в глобальной конфигурации. У каждого экземпляра свой производный ключ хранилища — например, `GENERIC_API_KEY__MY-OLLAMA`, — который заполняется в том же редакторе хранилища.

## Выбор конечной точки и модели

Задайте базовый URL и модель для модуля (или для каждого экземпляра) в его настройках глобальной конфигурации, а затем выберите модель для проекта на вкладке **Конфигурация**. **Правила маршрутизации** на вкладке «Маршрутизация» решают, какой модуль или экземпляр обрабатывает каждый язык.

## Получение учетных данных

Для **локального сервера** (Ollama, LM Studio, vLLM) учетная запись или ключ не нужны — достаточно базового URL (например, `http://localhost:11434/v1`) и заглушки в поле `GENERIC_API_KEY`.

Для **платного поставщика** порядок действий зависит от поставщика: создайте учетную запись, получите базовый URL API и ключ, убедитесь, что конечная точка использует формат OpenAI chat-completions, и только затем внесите ключ в хранилище.
