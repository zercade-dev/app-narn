# Использование Docker

## Обзор

Приложение поставляется как образ Docker вместе с `docker-compose.yml`, который поднимает **две службы**: `app` (обслуживает и API, и собранный интерфейс на одном порту) и **обязательную** базу данных `postgres`. Хранилище данных везде на Postgres, поэтому без него сервер не запустится. По умолчанию `docker compose up` скачивает опубликованный образ `:main` (`ghcr.io/zercade-dev/narn:main`) из GHCR и запускает рядом официальный Postgres 17.

## Предварительные требования

* Установлены **Docker** и **Docker Compose**.
* Образ приложения собран только для **amd64**. На Apple Silicon он все равно работает — Docker выполняет его через эмуляцию.
* Если образ приватный для вашей учетной записи, выполните `docker login ghcr.io` один раз (с токеном, у которого есть право `read:packages`) перед первой загрузкой.

## Запуск

Из папки, где лежит `docker-compose.yml`, — из корня исходников NARN:

```
docker compose up
```

Compose сначала запускает Postgres, дожидается его проверки работоспособности, затем запускает приложение. Как только приложение готово, откройте его по адресу `http://localhost:3001`.

Стек использует два именованных тома, чтобы данные сохранялись между перезапусками:

* **`translator-db`** — каталог данных Postgres, где хранятся ваши **проекты** и **память переводов**.
* **`translator-data`** — локальный файл хранилища плюс резервные копии и автоматические снимки для каждого проекта.

Postgres не публикует порт на хосте и находится во внутренней сети Docker, поэтому доступен только контейнеру приложения.

## Изменение порта хоста

Контейнер всегда слушает порт **3001** внутри Docker. Файл compose сопоставляет его с тем же портом на вашей машине:

```
ports:
  - "127.0.0.1:3001:3001"
```

Если порт 3001 уже занят, измените **левую (хостовую) часть** сопоставления — ту, что стоит перед вторым двоеточием. Например, чтобы обслуживать приложение на порту 8000:

```
ports:
  - "127.0.0.1:8000:3001"
```

Тогда приложение будет доступно по адресу `http://localhost:8000`.

**Не** меняйте переменные окружения `HOST` или `PORT` — они внутренние для контейнера (сервер внутри контейнера слушает `0.0.0.0:3001`, чтобы Docker мог перенаправлять на него трафик). Адрес на вашей машине определяет только хостовая часть сопоставления `ports`.

Префикс `127.0.0.1:` держит приложение привязанным к loopback-интерфейсу, сохраняя однопользовательский, локальный характер работы. Оставьте его как есть, если у вас нет намеренной причины открыть приложение наружу.
