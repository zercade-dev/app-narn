# Dockerの使い方

## 概要

このアプリはDockerイメージと、**2つのサービス**を起動する`docker-compose.yml`として提供されます：`app`（1つのポートでAPIとビルド済みUIの両方を提供）と、**必須**の`postgres`データベースです。ストレージはどこもかしこもPostgresを前提としているため、Postgresなしではサーバーは起動しません。既定では、`docker compose up`はGHCRから公開済みの`:main`イメージ（`ghcr.io/zercade-dev/narn:main`）を取得し、公式のPostgres 17をあわせて起動します。

## 前提条件

* **Docker**と**Docker Compose**がインストールされていること。
* アプリのイメージは**amd64**専用にビルドされています。Apple Siliconでも動作しますが、Dockerがエミュレーションで実行します。
* イメージがアカウントに対して非公開の場合は、最初のpullの前に一度`docker login ghcr.io`を実行してください（`read:packages`権限のあるトークンを使用します）。

## 実行

`docker-compose.yml`があるフォルダー — NARNのソースのトップレベル — で次を実行します。

```
docker compose up
```

Composeはまず先にPostgresを起動し、ヘルスチェックを待ってからアプリを起動します。アプリが正常に起動したら、`http://localhost:3001`で開けます。

このスタックは、再起動してもデータが残るように、2つの名前付きボリュームを使用します。

* **`translator-db`** — Postgresのデータディレクトリで、**プロジェクト**と**翻訳メモリ**が格納されます。
* **`translator-data`** — ローカルの保管庫ファイルと、プロジェクトごとのバックアップ・自動スナップショットです。

Postgresはホスト側のポートを公開せず、Dockerの内部ネットワーク上に置かれるため、appコンテナからのみ到達できます。

## ホスト側のポートの変更

コンテナは常にDocker内部でポート**3001**を待ち受けます。compose ファイルは、これをマシン上の同じポートにマッピングします。

```
ports:
  - "127.0.0.1:3001:3001"
```

ポート3001がすでに使用中の場合は、マッピングの**左側（ホスト側）** — 2つ目のコロンより前の部分 — を変更してください。例えば、ポート8000で提供する場合：

```
ports:
  - "127.0.0.1:8000:3001"
```

これで、アプリは`http://localhost:8000`から到達できます。

`HOST`や`PORT`の環境変数は**変更しないでください** — これらはコンテナ内部のものです（サーバーはコンテナ内で`0.0.0.0:3001`にバインドし、Dockerがそこへ転送できるようにしています）。マシン上のアドレスを制御するのは、`ports`マッピングのホスト側だけです。

`127.0.0.1:`という接頭辞は、アプリをループバックにバインドし続け、単一ユーザー・ローカル専用という前提を保ちます。アプリを外部に公開する明確な理由がない限り、そのままにしておいてください。
