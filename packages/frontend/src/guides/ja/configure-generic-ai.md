# Generic AIモジュール

## 概要

**Generic AI**モジュールは、OpenAI互換のAPIであれば何にでも接続できます — ホスティングされたプロバイダーでも、ローカルで動かすサーバー（Ollama、LM Studio、vLLMなど）でも構いません。キーは認証情報の保管庫に`GENERIC_API_KEY`として保存します。

**APIキーは任意です。** 認証を必要とするエンドポイント（有料のクラウドプロバイダーの多く）にのみ関係します。OllamaやLM Studioのようなローカルサーバーには本物のキーは不要ですが、保管庫は`GENERIC_API_KEY`欄が空でないことを要求するため、プレースホルダー（例：`local`）を何か保存しておいてください。

## 認証情報の保管庫にキーを追加

プロバイダーの認証情報は、プレーンな設定ファイルではなく、暗号化された**認証情報の保管庫**に保存されます。保管庫はセッションごとに一度、パスワードでロックを解除します。

1. サイドバーから**グローバル設定**を開いてください。
2. 保管庫をまだ設定していない場合は作成してください。保管庫のパスワードを決めて（セッションごとに再利用します）、ロックを解除してください。
3. **モジュールを有効化**の下で**Generic AI**を選択してください。必要なキーが未設定の場合、保管庫エディターが該当のキーを自動的に開きます。それ以外の場合は**認証情報の保管庫の管理**をクリックしてください。
4. 保管庫エディターで認証情報を追加してください。キー`GENERIC_API_KEY`を選び、**保管庫のパスワード**を入力して**保存**をクリックしてください。有料のエンドポイントの場合は、値として本物のAPIキーを貼り付けます。認証が不要なローカルサーバーの場合、キーは任意です — 空でないプレースホルダー（例：`local`）を保存するだけで構いません。

## インスタンスで複数のエンドポイントを実行

Generic AIは**名前付きインスタンス**に対応しているため、複数のエンドポイント（例えばクラウドプロバイダー1つとローカルサーバー1つ）を並べて登録できます。グローバル設定の**Generic AIのインスタンスをもう1つ追加…**を使用してください。各インスタンスは専用の保管庫キー（例：`GENERIC_API_KEY__MY-OLLAMA`）を持ち、同じ保管庫エディターで入力します。

## エンドポイントとモデルの選択

モジュール（または各インスタンス）のベースURLとモデルはグローバル設定の各設定で指定し、モデル自体はプロジェクトごとに**設定**タブで選択してください。どのモジュールやインスタンスが各言語を処理するかは、振り分けタブの**振り分けルール**が決めます。

## 認証情報の取得

**ローカルサーバー**（Ollama、LM Studio、vLLM）の場合、アカウントもキーも不要です — ベースURL（例：`http://localhost:11434/v1`）と、`GENERIC_API_KEY`欄のプレースホルダーだけで構いません。

**有料プロバイダー**の場合、手順はプロバイダーによって異なります。アカウントを作成し、APIのベースURLとキーを取得し、エンドポイントがOpenAIのchat-completions形式に対応していることを確認してから、キーを保管庫に入力してください。
