# 認証情報の保管庫

## 概要

プロバイダーのAPIキーは、プレーンな設定ファイルや環境変数には保存されません。**認証情報の保管庫** — 翻訳やAIレビューが認証情報を使う前に、ロックを解除しておく必要がある暗号化ストア — に保存されます。ロックの解除はブラウザーセッションごとに一度で、認証情報はメモリ上でのみ復号されます。

<!-- local-only -->
## パスワード保管庫（セルフホスト）

セルフホスト環境では、保管庫は暗号化されたローカルファイルです。最初のロック解除でこのファイルが作成されます：選んだパスワードが保管庫のパスワードになり、認証情報を保存するたびにファイルが再暗号化されます。パスワード自体は保存されません — パスワードがなければ、このファイルは復号できません。**グローバル設定**から、または*保管庫がロックされています*のカードから、ロックを解除できます。
<!-- /local-only -->

## デバイス紐づけの保管庫（クラウド）

クラウド版では、保管庫は**サーバー上で暗号化された状態**で保存されており、復号には2つの要素が必要です。

- **パスワード** — サーバーにもデバイスにも、どこにも保存されません。
- **デバイスごとの鍵** — デバイスを登録したときにブラウザー内で生成され、そのデバイスにのみ保持されます。

ロックを解除すると、両方の要素が暗号化された接続を通じて送られ、サーバー側で組み合わされて、**メモリ上に、そのセッション限りで**復号鍵が導出されます。どちらの要素も、導出された鍵も、サーバーのストレージに書き込まれることはありません — 保存されるのは暗号化された保管庫そのものだけです。そのため、サーバーに保存されたデータだけでは認証情報は明らかにならず、パスワードが漏れただけでも十分ではありません：ロックの解除には、登録済みのデバイスのいずれかも必要です。

グローバル設定にパスワード入力欄ではなく**保管庫ページを開く**ボタンが表示されている場合、デバイス紐づけの保管庫を使用しています — 設定・デバイスの登録・ロック解除・認証情報の編集・パスワードの変更は、すべて保管庫ページで行います。

## 知っておくべきこと

- 一度も使ったことのないデバイスは、ロックを解除する前に、保管庫ページで**登録**しておく必要があります。
- パスワードを紛失した場合（クラウドでは、登録済みのすべてのデバイスを失った場合も含む）、保管庫の内容は復元できません — 保管庫を新たに設定し直し、プロバイダーのキーを入力し直す必要があります。
- このアプリがログに記録する内容はすべて削除処理（redaction）を経るため、認証情報の値がログに現れることはありません。
