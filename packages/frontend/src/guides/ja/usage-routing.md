# 振り分けタブ

## 概要

**振り分け**タブは、各エントリをどのモジュールとモデルが処理するかを決めます。最初は単一のプロバイダーセレクターが開きます：プロバイダーを1つ選ぶと、プロジェクト内のすべてのエントリがそこへ送られます。ほとんどのプロジェクトでは、これだけで十分です。

送信先を複数使いたい場合は、タブを**詳細**に切り替えると、完全なルールビルダーが表示されます。ここでは、ターゲット言語・カテゴリ・エントリの長さによって振り分け先を変えたり、複数の名前付きルールグループを保持したりできます。タブは、直前にどちらを使ったかを記憶します。1つのプロバイダーより複雑な振り分けを行っているプロジェクトでは、どちらのモードを選んでも常にビルダーが表示されます — 既存の設定が隠れてしまうことはありません。

いずれの場合も、このタブが決めるのはエントリの振り分け方だけです。翻訳の実行自体は**翻訳**タブまたは**比較**タブから開始します。

## 振り分けルール

ルールは**詳細**ビューにあります。優先度順に評価され、エントリに最初に一致したルールが適用されます。各ルールは次の条件で一致を判定できます。

* **ソース** — インポートしたエントリのソース／出どころラベル。
* **エントリの長さ制限** — 文字数が指定の上限以下のエントリにのみ適用します。
* **ターゲット言語**と**カテゴリ**。

一致したエントリに対して、ルールは**モジュール**（および任意で**モデル**と**推論の強度**の上書き）と、任意のプロンプトのヒント（キャラクター、トーン、性別、メモ）を設定します。ルールは**ルールを追加**で追加します。変更はそのたびに自動的に保存されるため、覚えておくべき**保存**ボタンはありません。複数の名前付き**ルールグループ**を保持して切り替えることもできます（実行の進行中は切り替えがロックされます）。

## バッチのグループ化

振り分けタブには**バッチのグループ化**の設定もあります — 設定タブに表示されるものと同じ、プロジェクトごとの既定値で、対応する**バッチサイズの上限を無視**のトグルもあります。これにより、翻訳・評価・原文レビューの各実行で、関連するエントリが同じプロバイダーへのリクエストにまとまります。

## 翻訳の開始

1. **翻訳**タブまたは**比較**タブでエントリを選択します。
2. そこから**翻訳…**ダイアログを開きます — 再翻訳、翻訳メモリ、実行ごとのグループ化のオプションを選んで、実行を開始します。
3. 進捗・再試行・失敗は**アクティビティ**タブで確認します。
